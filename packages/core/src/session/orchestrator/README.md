# Main-Orchestrator foundation

This is an **incomplete, unprovisioned foundation**, not an available orchestration feature. The canonical Session `plan_document` remains the product plan. This document records ownership and safe integration boundaries, not a second plan.

## Responsibilities and boundaries

- The planning store owns revision-checked Main settings, proposals, dependency ordering, planning slots and resource reservations. An inbox row shaped as `user`, a parent ID, a proposal, or a reservation is **not execution authorization**.
- The checkout resolver supplies a physical Git checkout root shared by root/subdirectory Sessions, but not by independent clones or worktrees. Non-Git directories keep their physical directory identity. The store pins this identity and refuses later placement drift during configuration, planning and reservation. Filesystem resolution runs outside the write transaction; the transaction then rechecks Session placement. Moving a checkout requires a future explicit reconciliation procedure, never automatic re-anchoring. Callers must resolve file resources through the normal host file boundary before planning. String normalization cannot resolve symlink aliases of prospective file targets. Root and UNC keys remain distinct and normalized keys round-trip. macOS case folding is conservative and may over-block on case-sensitive volumes; only Windows was exercised here.
- Claimed tasks remain ownership evidence even if additive startup repair recreated an empty reservation table. An unknown repaired checkout identity blocks admission rather than freeing capacity. Missing non-defaulted required columns are not safely auto-repairable. This is not general corruption recovery: losing/recreating the task table or manually editing resource identities destroys ownership evidence and requires verified backup/reconciliation, not continued admission based on apparently empty tables.
- The mirror workspace adapter is in `packages/opencode/src/project/agent-mirror.ts`. It creates independent Git repositories and private working files, requests filesystem COW where supported, and safely uses copies otherwise. Git uses `/dev/null`, not Node's Windows device name. Borrowed Git objects are dissociated. No network sync, worktree creation, writable-hardlink fallback or physical-space saving is implied.
- Mirror manifests distinguish existing files, inherited tracked deletions and requested untracked files that were excluded (ignored or absent), respecting user/system ignore policy. Git filenames require valid UTF-8; sparse checkouts, tracked symlinks/submodules and unsupported portable paths are refused. Destination file modes are set and verified. Mirror-local `core.autocrlf=false` keeps child Git consistent with the byte basis; other Main repository-local settings are not inherited. Failures retain task-owned diagnostic directories. A future cleanup owner must verify `owner.json` and current contents; directory names alone are not ownership proof. Mirrors are not OS sandboxes.
- `session/fork.ts` captures a read-only, transactional provider-turn boundary at the exact current event sequence, with its context epoch, source history and observed model/agent. It refuses stale fences, pending/held inputs, incompatible epochs and unfinished tool pairs. It does not create a child, remap IDs, clone attachment ownership or attest authorization. Source entries are not clone-ready. Main may still own an activity between turns; this capture does not claim activity/background-job settlement. A future host snapshot operation must revalidate the event fence after filesystem capture and before provisioning. `AgentMirror` only records the caller's `throughSeq` label; its manifest is not proof of that recheck.
- `session/mirror.ts` prepares **content-only** B→K changes against current M and refuses partial patches on conflicts. Applying a returned patch still requires host permissions, reservations, the Session mutation journal and `FileMutation.transact`. Full integration must additionally preserve and guard file modes, including executable bits; a caller must refuse missing or differing mode evidence rather than silently applying a content-only patch. The current content seam is not a complete merge service.

## Lifecycle rules

A terminal task status does not prove that its child stopped writing. Never release slots or reservations merely on `done`, `failed`, `cancelled`, a cache miss, an archive toggle or process expiry.

`releaseUnstarted` only releases paused/terminal tasks with no bound child, including an archived Main's own task. For an unstarted paused proposal, release it, transition to `waiting`, then reserve again. Exact proposal retries reconcile; state mutations require the current task revision, and callers reconcile lost replies by reading stored tasks before another mutation.

`assignChild` and `settleChild` are **store seams only** — no runtime wiring calls them yet. `assignChild` binds one existing parented child session to a snapshotting/starting task atomically and idempotently, refuses foreign/missing/Main-role candidates and never frees the slot. `settleChild` releases slot and reservations solely from durable evidence that the bound child can no longer write (no unpromoted inputs, no queued/active questions, no running/recovering activity, at least one recorded activity); a terminal task state alone never settles, an idle child with zero activities fails closed, and the child link is retained as provenance. Binding is not host attestation, fork provisioning or permission inheritance. Do not introduce a model-controlled `settled: true`, delete/clear a child link to evade that check, or use `ON DELETE SET NULL` to turn a started child into an apparently unstarted task. Child/input foreign keys currently retain that evidence. Main deletion cascades its planning records; cold archival excludes Mains and referenced children because the archive format does not preserve these records yet.

A cache result of `low` or `unknown` parks that child. With interaction on, Main chooses the approved Main-only or separately authorized ordinary-subagent route; with interaction off, Main continues. Do not add an automatic cache retry/warm-up lane or a blind `blocked_cache -> running` transition. The configured threshold is captured per proposal; the current interaction toggle remains live so changing it affects unresolved decisions.

## Required integration gates

Do not expose or provision these services solely because `experimental.session_orchestrator` decodes as true. The flag is optional/default-off in both config dialects and survives V1 migration, but it currently activates no runtime behavior.

Still required: real-user host assignment attestation; inherited model/variant/permission ceilings; SessionExecution-bound child admission/settlement; consistent V2 history/context forks; first-request tool withholding and provider usage delivery; delegated Question provenance; host/API/SDK orchestration operations; personal skill and thin toolbar controls. No UI, live provider-cache, deployment or installed-runtime acceptance is established by foundation tests.
