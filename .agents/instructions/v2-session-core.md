## V2 Session Core

- Main-Orchestrator work is currently an unprovisioned foundation. Keep real-user host attestation, inherited policy/model ceilings, execution-owner admission/settlement, and first-request cache tool withholding as hard integration gates; a task row, user-shaped inbox record, feature flag or terminal status supplies none of that authority. Reuse the existing execution, Question and mutation-journal boundaries. See `packages/core/src/session/orchestrator/README.md` for current boundaries and evidence.
- Resolve physical checkout placement outside SQLite write transactions, then recheck placement and pinned identity under the existing immediate transaction before configuration, planning or reservation. File claims must use canonical host-resolved paths (including drive roots and UNC spelling); string normalization alone cannot resolve symlink aliases. Read-only fork capture is a consistent provider-turn snapshot, not child creation or proof that the source activity settled; revalidate its event fence after workspace capture before any future provisioning.

- Agent communication reuses the existing `session_send`/`session_read` tools
  and never adds parallel group, presence, grant, or dispatch machinery.
  `session_send` targets one existing Session by its exact ID — the user's
  explicit coordination request is the semantic authorization, regardless of
  open tabs or busy/idle state, across projects. It creates no Session, needs
  no skill activation, and replies go back via `session_send` to the
  provenance Session ID within the commissioned exchange only. No broadcast,
  no polling loops, no Shell/HTTP/SQLite/`spawn_agent` fallback. Each new
  visible normal session still needs its own `spawn_agent` approval.
  `session_read` stays a separately commissioned history read with its own
  permission and must not run implicitly during communication.
- Keep durable prompt admission separate from model execution. `SessionV2.prompt(...)` admits one durable `session_input` row before scheduling advisory `SessionExecution.wake(sessionID)` unless `resume: false` requests admit-only behavior. The serialized runner promotes admitted inputs into visible user messages at safe boundaries.
- Reusing a Session ID adopts the existing Session. Reusing a prompt message ID reconciles an exact retry only when Session, prompt, and delivery mode match; conflicting reuse fails. Historical projected prompts lazily synthesize promoted inbox records during exact retry.
- Keep `SessionExecution` process-global and Session-ID based. Its local implementation owns the process-local Session coordinator and discovers placement through `SessionStore` plus `LocationServiceMap.get(session.location)` only when a drain starts; no layer should take a Session ID. V2 interruption targets the active process-local ownership chain for that Session; idle or missing interruption is a no-op.
- Keep `SessionRunner`, model resolution, tool registry, permissions, and filesystem Location-scoped. Omitted `Location.workspaceID` means implicit-local placement; explicit workspace identity remains reserved for future placement semantics.
- Preserve one explicit `llm.stream(request)` call per provider turn and reload projected history before durable continuation. Do not bridge through legacy `SessionPrompt.loop(...)` or delegate orchestration to an in-memory tool loop.
- Bound framed provider-stream waits independently of consumer processing: keep a finite initial deadline, and grant any provider-specific longer idle phase only after meaningful model progress. Keepalives and lifecycle chatter must not refresh the deadline; explicit timeout overrides apply to every phase. Preserve immediate provider failures and cancellation, and cover phase transitions, dead streams, keepalives, errors, and interruption with short-duration tests.
- Keep local Session drains process-local until clustering is implemented. `SessionRunCoordinator` joins explicit same-Session resumes, coalesces prompt wakeups, and allows different Sessions to run concurrently. Advisory wakes drain eligible durable inbox rows only; post-crash activity recovery requires a separate explicit design before it may retry provider work. A sequenced interrupt suppresses stale advisory wakes, not later explicit `queueContinuation` requests (including tool-cancellation and controlled-question replies); a later stop may still suppress a continuation queued before it. Test both orderings and cleanup serialization.
- Keep delivery vocabulary explicit. Prompts steer by default and coalesce into the active activity at the next safe provider-turn boundary. Explicit `queue` inputs open FIFO future activities one at a time after the active activity settles.
- Keep EventV2 replay owner claims separate from clustered Session execution ownership.
- App-plugin event payloads are shared with host reducers and other listeners. Copy session metadata before normalizing directory spelling; never mutate an incoming session's placement. The transport scope `global` is a pseudo-scope, not a project path, and must not replace the payload directory. Cover global-scope delivery and immutable payloads for session-created and session-updated events.
- Scope-less session events (published outside any instance, for example while the owning project instance bootstraps) must be re-keyed onto their owning project directory at the host transport layer before any emitter, reducer, or plugin sees them: payload `info.directory` first, then placement learned from earlier session metadata in the same queue batch, then the known-session index over directory stores; unknown sessions and non-session events (`project.updated`, `global.disposed`, heartbeats) keep the global scope. Cover payload-directory routing, learned-placement ordering across queued follower events, known-session routing, and unknown-session passthrough with unit tests.
- In app session navigation and tabs, reconcile durable activity and status snapshots together: a newer busy snapshot must clear an older settled marker, while a response captured before a terminal event must never revive it. Preserve semantic title updates against older in-flight session-list responses and route low-volume title sync events to inactive directories. Cover these orderings with regression tests.
- V2 turn-completion evaluation must receive history from `session_message`, not assume that legacy `message`/`part` rows exist. Pass bounded chronological user/assistant evidence through the shared evaluator and plugin policies; cover successful final reports with stale todos and empty legacy history, while retaining failure and policy vetoes.
- Keep the System Context algebra, registry, and built-ins in `src/system-context`; keep Context Source producers with their observed domains, and keep Session History selection plus Context Epoch persistence Session-owned.
- Every regular Session runner request must expose its authoritative UI-host identity (`app`, current `sessionID`, nullable `parentSessionID`, main/child role) from the loaded Session, independently of provider backend IDs and legacy plugin hooks. Add it after plugin transforms; rederive it on tool continuations and later turns rather than persisting a guessed ID. Child identity never authorizes acting as the parent. Do not inject main-workflow context into title/vision helper requests. Verify the actual captured runner requests without a plugin, including child ancestry and root continuation; a directly invoked legacy hook is not evidence of Core delivery.
- LM Studio context budgets must use the loaded instance's `loaded_context_length`, not its architecture's `max_context_length` or a stale configured context. Keep discovery shared across legacy and V2 provider paths, refresh limits on catalog rebuilds (including model aliases), and preserve configured limits on unavailable or invalid metadata. Default compaction headroom is 10% of the effective input budget capped at 20,000 tokens; explicit `compaction.buffer` overrides it. Apply the same headroom to automatic, manual, summary and model-switch budgets, with regression tests through the real catalog and runner adapter.
- The AISDK fallback must receive the runner's resolved, provider-matching stored key as transport-only options, without inserting secrets into catalog models. Preserve explicit SDK-key precedence and environment fallback; invalidate language reuse when the effective stored key changes or disappears. Diagnose connected providers from Integration/Credential state, not only `provider` blocks or legacy `auth.json`. Free composer selection requires no hard-coded `build.model`/`variant` or project-pinned build chain; never substitute one fixed route for another or test against a developer's personal config. A stored direct model remains direct even when `chain` is omitted: provider recovery must not attach the agent's fallback chain. Only an explicitly selected chain authorizes failover; cover direct-choice failures and configured-chain recovery through the real runner. Before claiming the desktop contains a credential fix, verify its installed Node-sidecar route, not only the last successful deploy status.
- AISDK fallback requests must flatten the initial system parts into one leading system message. Preserve chronological operator updates at their original position as XML-escaped `<system-update>` user text, matching native routes; never hoist them or silently discard non-text updates. Convert attachment data URLs to decoded bytes and remote HTTP(S) URI strings to SDK URL values, preserving raw base64/bytes and filenames. Verify the real SDK's serialized HTTP body (fresh text chat, post-compaction updates, image and document data), not only a successful minimal provider call; a repeated data-URL header causes image decode failures even with a valid key.
- Unlimited durable history does not enlarge provider working context. Manual compaction must use the stored Session Location's normal model resolver and real LLM summarizer, preserving original messages, context epochs, open todos, queued inputs, and ownership without implicitly resuming execution. Verify actual SessionV2 and HTTP boundaries, not only prompt helpers. Model-switch preflight can compact too: both HTTP endpoints must map summary failures to a declared 503 and message-decode failures to a declared 500 with a non-sensitive error reference; regenerate the SDK when these contracts change.
- Across provider turns and compaction, authoritative raw provider errors override synthetic stream-cleanup retry hints: authentication and non-retryable HTTP 4xx failures must not become transient retries or successful fallback summaries, even when nested text says `server_error` or a provider-error event marks the failure retryable. Retain bounded retries for genuinely transient failures; cover synthetic-onHalt followed by raw failure and actual HTTP serialization. Persist observed context-overflow classification through the typed Step.Failed contract. Prove durable activity settlement with LocalExecution, not a coordinator-only fixture.
- Permission safety-review intent must come from bounded durable `session_message` dialogue, not the compacted model context. Resolve the source assistant within the same Session, anchor at the latest real user message with non-whitespace text before it, bound the examined candidate rows (`SessionHistory.CANDIDATE_ROW_LIMIT`), apply JavaScript trim semantics when counting meaningful dialogue so whitespace-only rows never consume the budget, and exclude later user instructions, synthetic messages, compaction summaries, reasoning, and tool output. Preserve explicit deny rules and single-use host consent; never fix missing intent by broadly allowing `git *` or `Get-*`. Cover post-compaction Git/Get calls, whitespace-only dialogue, candidate-window exhaustion, envelope truncation signaling, and missing, foreign, and non-assistant source boundaries.
- A rollback may restore files only from the Session file-mutation journal with verified range ownership, uninterrupted before/after journal continuity, and unchanged expected hashes. Use the shared `FileMutation.transact` locks and guarded multi-target preflight rather than direct filesystem writes; a missing journal or unresolvable conflict blocks file rollback. Snapshot/patch history does not establish authorship. The explicit `files: "messages_only"` operation retains the worktree and may clear the blocked message range after the user chooses it. Do not run a writing repair agent or silently fall back to Git snapshot restoration.
- Keep rollback dialogue recoverable until replacement prompt admission commits cleanup. Repeated checkpoints apply only the journal delta; failed transitions must retain the already-applied checkpoint for retry and unrevert. Block prompt admission while restoration is unresolved. Use chronological message boundaries, not lexical V1/V2 ID comparisons, and keep asynchronous recovery scoped to the originating session. Verify reload, Message/Both/Checkpoint recovery, conflict choices, continuation after compaction, and long-session paging.
- Production V2 turn-completion must share the same process-local `SessionExecution` coordinator used by HTTP Session handlers; forward that runtime layer outward with `Layer.provideMerge` rather than building a second `SessionExecutionLocal.layer` or relying on sibling service layers. Keep failed and interrupted activities from auto-resuming; cover production wiring and all three terminal statuses with regression tests.
- Provider-stream inactivity is measured only while awaiting the next provider pull; meaningful content/tool progress moves to a finite 240-second window for GLM-prefixed IDs and OpenAI GPT-6 IDs, while explicit timeout overrides replace both phases. Preserve raw aborts as distinct from measured inactivity and normalize them at the runner boundary as retryable `stream-aborted`. Accept a summary cleanup abort only after `finish`, and still require non-whitespace summary text. A clean summary close without usable text is typed `SummaryFailed` whether or not a finish event arrived.
- Production runner and compaction must use the shared `session/provider-stream.ts` helpers; regression tests must exercise the runner exports too, not a disconnected copy. Blank timeout overrides retain defaults, provider-error events are not progress, and disabling the inactivity guard must not disable abort classification. A provider-error followed by clean EOF must fail the activity when bounded retry/chain continuation is unavailable or exhausted; never let a persisted Step.Failed silently settle as completed. Verify unchanged red/green checks, managed normal admission, cancellation, and advisory wake without replay.
- Own one five-attempt provider recovery allowance per activity, shared by pre-provider failover, request retries, partial-output continuation, configured chains and empty completions. Successful tools never reset it. After durable output, reload projected history for a fresh turn rather than replaying the previous request or completed tools. Honor that allowance on the step-limit final-answer lane with tools still disabled; a failed final response must never become `Activity.Completed`. Known terminal auth/quota events outrank locally-generated cleanup aborts or inactivity hints; genuine raw provider failures and actual interrupts retain precedence. Schema-invalid StructuredOutput blocks every retry and chain lane after successful sibling tools settle. Empty-completion handling must exclude already-observed provider failures. Keep real stops and pending/dismissed human questions as boundaries. Verify these cases through `SessionAccess.send` -> managed `SessionExecutionLocal`, including mixed-budget exhaustion, exactly-once tools and advisory wake without replay; never substitute an `expect(true)` pointer for an executable contract.
- Preserve the provider's full Retry-After deadline. Automatic waits beyond five minutes settle with a durable `retry-deferred` failure instead of holding an activity open or issuing an early retry; this wait limit is separate from the normal 30-second backoff ceiling. Prove deferral with a short controlled regression that records an incorrectly scheduled distant retry and stops only the isolated fixture, not the installed app.
- SDK request rejections, readable-stream failures and error parts must retain HTTP status, safe response diagnostics and the full Retry-After through retry events and durable failure publication. Never reduce APICallError to message text or let reader cleanup replace its response facts. Share the native Retry-After parser (milliseconds, seconds and HTTP dates); blank/malformed millisecond values must not mask a valid fallback. Classify tokens-per-minute/TPM exhaustion before generic token/context wording, while keeping auth, permanent HTTP 4xx and account quota terminal. Prove bounded retries, full deadlines, deferred waits, interruption and exactly-once tools through real SDK HTTP and normal managed Session admission.
- Native HTTP and SDK quota decisions must use the shared LLM quota classifier. Cerebras `token_quota_exceeded` with an explicit minute/TPM window is transient even when `param` is `quota`; daily or ambiguous token limits and explicit account/credit/period signals remain terminal. Reproduce the complete observed response (`message`, `code`, `type`, `param` and Retry-After), not a simplified message-only fixture. Prove the captured 59/60-second deadlines with a controlled test clock and exercise the same payload through real SDK/native HTTP and durable Session recovery.
- At LLM route boundaries, preserve Effect causes containing interrupts before mapping provider stream failures. Keep undici `TypeError: terminated` / nested `SocketError: other side closed` as retryable transport reads, and keep body `AbortError` failures distinct and non-retryable. Verify actual HTTP classification plus bounded normal-admission/LocalExecution settlement, including no `Activity.Completed`, no advisory replay, and no repeated execution of completed tools.
- Persist malformed provider tool input as a failed, non-executable tool call and permit only bounded correction turns; a malformed call on the final step-limit turn fails the activity instead of completing it. Verify normal prompt admission through its managed LocalExecution wake as well as explicit resume, including failed settlement, no `Activity.Completed`, and no advisory replay. If context-overflow compaction fails, persist the original typed overflow on `Step.Failed` before surfacing the summary failure, including a raw pre-finish `AbortError`. If the provider stream itself is interrupted after an overflow event, skip summary recovery and suppress that failure evidence. Never convert actual interruption into provider failure or let a synthetic overflow hint override a later raw provider failure.
- Distinguish a provider child stream returning an interrupt from external owner/process cancellation. Preserve its Effect interrupt cause and attach a narrow runner marker only when the outer stream race and tool settlement completed without external interruption. LocalExecution then terminalizes only that activity as interrupted, without retry or compaction, and leaves sibling owner leases untouched. Explicit human stop has priority. Genuine owner shutdown remains recoverable with an expired lease, not a terminal activity; cover both lifecycle paths and managed advisory wake without replay.
- A published provider failure blocks retry inside the same failed publisher; authorized continuation must start a fresh turn. Capability rebuilds and overflow recovery cannot bypass interrupt, terminal-event, schema or budget checks. Reject unexpected final-lane tools before plugin hooks or execution. Missing required StructuredOutput must fail when correction is exhausted on both normal and final lanes. Publish exactly one terminal Step.Failed for the same schema violation or retry deferral. Summary retries also preserve the full Retry-After deadline and defer excessive automatic waits; do not shorten the provider deadline to a backoff ceiling.
- Composer model, chain, variant and agent selections must share serialized writes and stale-readback protection across dock-tab remounts, keyed by server, directory and Session. Keep the newest explicit choice until its write is acknowledged and confirmed; distinguish earlier queued local writes from newer external selections. Clone prior Solid store state before mutation so a rejected write can restore it; when successive writes fail, walk failed predecessors back to the last successful selection. Keep write queues Session-local and recover their serialization tail after failures; report a failed write once to that Session's submit gate rather than poisoning sibling Sessions or every future submit. Preserve pending guard data across remounts, but detach disposed receiver callbacks and release completed queue entries. Verify delayed ACKs, remounts, rapid picks, rejection, newer canonical readback, reload and the actual next prompt model; never let a stale picker re-submit the Session's initial chain.
